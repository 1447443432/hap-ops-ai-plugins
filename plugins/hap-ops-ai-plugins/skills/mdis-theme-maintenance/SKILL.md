# MDIS 主题维护

处理 MDIS 主题适配、新页面或新增控件的主题问题时使用。先阅读项目及前端 `AGENTS.md`，复用 `frontend/src/styles/theme-tokens.less`、`variables.less` 和 `App.jsx` 中的主题变量；优先修复共享样式，不为单页重复覆盖。保留状态颜色语义和原有交互，避免只调整正常态。

检查受影响页面的标题、正文、次要和禁用文字、图标、分割线、表格、分页、输入框、选中项及空状态；涉及按钮、弹窗或提示时覆盖加载、禁用、悬停、焦点、确认框和消息提示。对直接使用固定浅色的新增页面留意其嵌套表单是否已经继承深色主题，避免深色文字落在深色控件或白色容器上。

比较同一菜单、列表或按钮组中承担同类操作的相邻项：分别检查普通、鼠标悬停和键盘焦点状态的背景、文字和轮廓是否一致；有明确语义差异的危险操作等保留相应区分。不要把悬停态误当作持久选中态处理。

LESS 中被 `mix`、`fade` 等函数使用的颜色不能直接替换成 CSS 变量；优先在具体 CSS 属性使用 `var(--mdis-..., 原值)`，并检查局部样式优先级。Ant Design 静态消息和门户弹窗可能不继承 React 主题上下文，应在实际 DOM 中验证；不要仅依据组件外观或样式源码断定结果。

按项目的 `mdis-browser-visual-check` 技能进行实际浏览器检查，覆盖相关浅色、深色与桌面、窄屏场景；只读操作，不提交业务数据。对加载瞬态、真实数据、跨域页面或不能复现的状态，明确说明未验证范围。根据改动范围运行最小测试和构建，并将用户要求记录的问题更新到项目问题记录。

每次发现可复现且可复用的新问题时，精简地补充到本技能或现有视觉检查技能，注明适用条件；不要把猜测写成通用规则，也不要替代具体问题记录。
