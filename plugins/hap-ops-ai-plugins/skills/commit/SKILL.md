# Git 提交

按照“简体中文标题 + 分组正文”的格式，生成本地 Git 提交说明并创建提交。

## 使用方式

```text
/commit
```

当用户希望分析已暂存改动并创建本地提交时使用。在支持 skill 快捷命令的界面中，`/commit` 可作为触发语。

## 执行流程

1. 使用 `git diff --staged --stat` 和 `git diff --staged` 检查已暂存改动。
2. 如果没有已暂存改动，明确告知用户，并且不要创建提交。
3. 生成简体中文提交说明，格式为一句自然的中文标题加若干分组正文。
4. 除非用户只要求生成草稿，否则使用生成的提交说明创建提交。
5. 完成后报告提交哈希，以及本次执行过的检查或人工审查内容。

## 提交格式

```text
一句自然的中文标题

分组标题:
- 说明具体改动
- 说明行为变化、原因或影响

[可选的其他分组]:
- 说明其他相关改动
```

## 语言规则

- 标题、分组标题和正文条目使用简体中文。
- 除非用户明确要求，否则不要使用 `feat:`、`fix:`、`chore:`、`docs:` 这类约定式提交前缀。
- 代码标识符、命令、接口路径、产品名和协议名可以保留原文，例如 `go test ./...`、`/api/tasks`、`Redis`、`FLUSHALL`、`MongoDB`、`MinIO`。
- 避免使用“更新代码”“修复问题”这类模糊说明；要写清楚具体行为、范围或原因。
- 标题用一句话概括整个提交，正文再按类别拆分细节。

## 常用分组

只选择与已暂存改动匹配的分组。常用分组如下：

- `新增功能:` 用于新增能力、页面、接口、流程或用户可见行为。
- `优化调整:` 用于架构、交互、样式、性能、可维护性或行为细节优化。
- `Bug 修复:` 用于缺陷修复，并说明触发场景和修复后的行为。
- `安全加固:` 用于敏感信息、权限、输入校验、注入防护、路径安全或破坏性操作防护。
- `影响范围:` 用于说明受影响的模块、页面、接口、任务或运行流程。
- `测试:` 用于说明新增或调整的测试，以及覆盖的回归场景。
- `文档:` 用于说明 README、AGENTS.md、部署文档或使用指南的更新。

## 项目规则

在特定项目内工作时，如果存在项目级提交说明指南或 `AGENTS.md`，先读取这些文件，再遵循其中规范。项目约定优先于本 skill 的示例格式。

如果已暂存改动跨越多个模块，正文应按有用的分组组织，而不是机械罗列文件名。若改动涉及凭证、数据库密码、MinIO 密钥、MongoDB URI 处理、路径校验、自定义命令参数、任务取消、破坏性操作或 worker 执行，应在提交说明中明确体现相关安全影响。

## 示例

```text
修正 Redis 清空任务执行目标

Bug 修复:
- Redis 清空 worker 使用任务创建时持久化的 resolvedAddress，避免哨兵主节点变化后执行到新的目标
- 从任务记录恢复 Redis 清空预览信息，保持 worker 执行目标与确认信息一致

安全加固:
- MinIO Access Key 输入框改为密码类型，避免前端明文展示访问凭证

测试:
- 新增 Redis 哨兵模式 worker 使用已确认主节点的回归测试
```

## 草稿示例

```text
优化任务路径与概览信息展示

优化调整:
- MySQL/MongoDB 导出产物目录改为 mysql-export / mongodb-export，并保留旧任务展示路径兼容
- 任务概览在任务名称旁展示数据源名称与地址，覆盖导出、导入、同步、校验和 MongoDB 组织 ID 修改任务

影响范围:
- 任务列表详情、导入产物选择、数据源配置、MinIO 同步参数
```
