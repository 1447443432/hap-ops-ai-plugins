# 模板：交付清单

## 出几份（与部署/运维 A/B 独立成档对齐）
- **按版本各出一份**：标准版、专业版、精简版，共 3 份（清单内把该版本的部署 A/B、运维 A/B 两份分别列出；架构图也列 A/B 两套）。
- 文件名：`HAP交付清单_集群标准版.docx` / `_集群专业版.docx` / `_集群精简版.docx`。
- 标准版/专业版清单引用 13 项（2 PDF + 部署A/B + 运维A/B + 迁移 + 架构图A/B 各 svg/png + 凭据表 + 技能zip）；精简版 9 项（不分场景）。
- 封面用 inject_cover.py 照搬（标题"交付清单（集群标准版）"等）。
- **核对规则**：生成后 ls /mnt/user-data/outputs/ 逐项比对清单引用=实际文件，不符则改清单。

> 生成顺序第7位，引用前面所有产物 → 生成后必须按实际 outputs 目录核对（constraints.md E）。
> 出厂快照：source-cache/checklist.json。客户名【仅】出现在本文档正文“项目基本信息”，不进文件名。

## 文档元信息
- 标题：`HAP交付清单`／`HAP Delivery Checklist`（不带客户名/场景）

## 章节骨架
| 章节 | 内容 |
|---|---|
| 一、交付概述 / 项目基本信息 | **客户名、项目编号、交付日期、域名、版本类型**（来自参数表） |
| 二、交付文档清单 | 列出本次实际产出的全部文件（见下，按实际核对） |
| 三、文档详细说明 | 每份文档一节，说明用途/适用范围 |
| 四、文档验收记录 | 空表待签 |
| 五、部署交付验收清单 | 勾选项（部署完成度核对） |
| 六、后续支持与归档（6.1 支持渠道/6.2 更新策略/6.3 归档建议） | 渠道按品牌(mingdao/nocoly) |
| 七、双方签字确认 | 空白签字区 |

## 易错提醒
- 不要引用未实际产出的文件（如未选迁移却列了迁移文档）。
- 凭据登记表在清单中列出，文件本身留空待客户填。
