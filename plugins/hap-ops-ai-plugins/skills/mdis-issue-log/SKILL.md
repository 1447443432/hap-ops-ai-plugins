# MDIS 问题记录

维护 `docs/issues/index.html`，使用可独立打开的 UTF-8 页面记录问题。

- 按发现日期分组：每个日期作为大标题，日期下每个问题作为独立小标题和案例。桌面端使用左侧固定目录，窄屏时目录回到正文上方；目录按日期分组，问题标题链接到对应案例的稳定锚点；新增或修改标题时同步目录。日期未知时归入“日期未知”，不要编造日期。
- 新问题追加至对应日期，不覆盖其他案例；同一问题出现新进展时更新原案例并保留必要历史。日期组按时间倒序，目录和正文顺序一致。
- 每个案例记录发现时间、记录时间和最后更新时间，写明时区；事件具体时间不确定时标为“具体时间未知”，不要用记录时间冒充发生时间。更新案例时保留发现时间并刷新更新时间。
- 详细记录发生环境、触发操作、实际表现、影响范围，以及用户提供的报错原文或经脱敏的日志片段、错误码和相关接口；使用 HTML 转义后的代码块展示。没有原始报错时如实说明，不推测具体日志或状态码。
- 记录排查证据、已确认的根因、具体修改位置和处理方案、执行的验证及结果、待验证事项；明确区分推测与已验证事实，不把测试通过等同于现场验证完成。
- 不记录密码、令牌、内部地址或客户数据。引用项目文件时使用相对路径，页面不依赖外部资源即可阅读。
- 新证据改变结论时更新已有案例，保留必要的处理历史；不要把未验证的处理标记为已完成。
- 修改后检查 UTF-8 编码和 HTML 格式。
- 发现反复出现的具体需求时，结合实际案例完善本 skill；保留用户已有要求，不擅自扩大适用范围。
